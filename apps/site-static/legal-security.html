Segurança

Segurança desde a primeira versão operacional.

O FitCore Pro está em validação inicial. A regra é simples: não expor serviços internos, não servir mídia de terceiros sem licença, não publicar segredos e separar claramente interface, API e componentes internos.

Acesso seguro

O acesso público deve ocorrer por HTTPS no subdomínio oficial. Serviços internos, como o motor fitness e a API local, não devem ficar expostos diretamente para a internet.

Segredos e chaves

Chaves JWT, SECRET_KEY, senhas de banco, tokens e credenciais de integração devem ficar fora do GitHub e ser rotacionados caso apareçam em terminal, log ou conversa.

Backups

Backups precisam existir antes de mudanças estruturais. O restore deve ser testado antes de considerar a operação pronta para cliente real.

Auditoria

Operações sensíveis devem gerar trilha de auditoria: quem alterou, o que alterou, quando alterou e qual impacto teve para aluno, professor ou gestor.

Checklist mínimo antes de produção comercial

  • HTTPS ativo e redirecionamento HTTP para HTTPS.
  • Portas internas bloqueadas para acesso público.
  • Senhas padrão removidas.
  • Chaves e tokens fora do repositório.
  • Política de privacidade e termos publicados.
  • Backup e restore testados.
  • Logs técnicos sem dados sensíveis desnecessários.
  • Controle de acesso por perfil: gestor, professor, aluno e suporte.
